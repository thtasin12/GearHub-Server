# GearHub Server

Express + TypeScript backend for **GearHub**, an equipment-rental marketplace. The API manages authentication, users and roles, equipment listings, availability, bookings, Stripe Checkout payments, and marketplace operations.

**Production API:** https://gearhub-server.onrender.com  
**Health check:** https://gearhub-server.onrender.com/health

## Tech stack

- Node.js 20+
- Express 5 and TypeScript
- MongoDB with the native MongoDB Node.js driver
- Better Auth with MongoDB adapter and JWT plugin
- Stripe Checkout and signed webhook verification
- Helmet, CORS, rate limiting, and `node-cron`

## Features

- Email/password authentication and optional Google OAuth
- Better Auth sessions and short-lived JWTs for protected API requests
- Server-controlled roles: `customer`, `owner`, and `admin`
- Equipment creation, editing, moderation, search, filtering, comparison, and availability checks
- Booking creation with server-side rental-price calculation and temporary payment holds
- Stripe-hosted Checkout with webhook-based payment confirmation
- Payment history and admin-initiated refunds
- Favorites, reviews, profile management, notifications, conversations, and messages
- Rental extensions, pickup/return handover records, and booking tracking
- Customer, owner, and admin analytics
- Scheduled cleanup of expired unpaid bookings and completion of ended paid rentals

## Project structure

The backend application is intentionally kept in a single TypeScript entry file:

```text
gearhub-server/
├── node_modules/
├── dist/                 # Generated by the TypeScript build
├── package.json
├── tsconfig.json
└── server.ts
```

Environment files such as `.env` are local-only and must not be committed.

## Local setup

1. Clone the repository and install dependencies:

   ```bash
   git clone <YOUR_SERVER_REPOSITORY_URL>
   cd gearhub-server
   npm install
   ```

2. Create a local `.env` file in the project root and configure the variables shown below.

3. Start the development server:

   ```bash
   npm run dev
   ```

4. The API runs at `http://localhost:5000` by default. Check it at:

   ```text
   http://localhost:5000/health
   ```

### Available scripts

```bash
npm run dev      # Run server.ts with tsx watch
npm run build    # Compile TypeScript into dist/
npm start        # Run dist/server.js
```

Use `npm run build` before `npm start` in a production environment.

Create `.env` locally. Use your own credentials; never copy secrets into this README or commit them to GitHub.

## Authentication and authorization

Better Auth is mounted at `/api/auth/*`. Its Express handler is registered before `express.json()` so the authentication handler can read the original request body.

Protected API requests use a Better Auth JWT in the `Authorization` header:

```http
Authorization: Bearer <BETTER_AUTH_JWT>
```

The API verifies JWTs against the Better Auth JWKS endpoint and checks the current user record in MongoDB. The current database role and blocked status are therefore enforced on API requests.

New accounts receive the `customer` role. Users cannot select their own role during registration. Admins can promote customers to owners or admins using the admin user-management endpoint.

### Google OAuth callback

Configure the following authorized redirect URI in Google Cloud Console:

```text
http://localhost:5000/api/auth/callback/google
```

For production, use:

```text
https://gearhub-server.onrender.com/api/auth/callback/google
```

The frontend origin must also be included in the backend's `CLIENT_URL` and `CLIENT_URLS` settings.

## Stripe Checkout and webhook flow

1. The customer creates a booking using `POST /api/bookings`.
2. The server calculates the rental amount from the stored equipment price, rental dates, rental type, and requested quantity. The client does not supply a trusted total.
3. The customer requests a Checkout Session through `POST /api/payments/checkout/:bookingId`.
4. The browser is redirected to the Stripe-hosted Checkout page.
5. Stripe sends an event to the backend webhook endpoint:

   ```text
   https://gearhub-server.onrender.com/api/payments/webhook
   ```

6. The backend verifies the Stripe signature using `STRIPE_WEBHOOK_SECRET`. A verified successful payment updates the payment and booking records. The frontend success redirect alone is not treated as proof of payment.

Configure a **Snapshot** webhook destination in Stripe Test mode and subscribe to:

- `checkout.session.completed`
- `checkout.session.async_payment_succeeded`
- `checkout.session.async_payment_failed`
- `checkout.session.expired`

Copy that destination's signing secret into the Render environment variable `STRIPE_WEBHOOK_SECRET`. The Stripe secret key and webhook signing secret must belong to the same Stripe mode (Test or Live).

For local webhook testing with Stripe CLI:

```bash
stripe listen --forward-to localhost:5000/api/payments/webhook
```

Use the signing secret printed by Stripe CLI for that local listener. Do not use a Dashboard endpoint secret for a different webhook destination.

## Deployment (Render)

Suggested Render settings:

- **Build command:** `npm install && npm run build`
- **Start command:** `npm start`
- **Health check path:** `/health`

Set all environment variables in Render's Environment page. For the current GearHub deployment, the frontend origin is:

```text
https://gear-hub-client-yken.vercel.app
```

Use the following production origins:

```env
CLIENT_URL=https://gear-hub-client-yken.vercel.app
CLIENT_URLS=https://gear-hub-client-yken.vercel.app,http://localhost:3000
BETTER_AUTH_URL=https://gearhub-server.onrender.com
STRIPE_SUCCESS_URL=https://gear-hub-client-yken.vercel.app/payment/success?session_id={CHECKOUT_SESSION_ID}
STRIPE_CANCEL_URL=https://gear-hub-client-yken.vercel.app/payment/cancel
```

Also:

- Allow the Render service to connect to MongoDB Atlas and use a database user with appropriate limited permissions.
- Configure the production Google OAuth callback URL if Google sign-in is enabled.
- Create a Stripe webhook destination for the deployed endpoint and store its signing secret in Render.
- Keep `.env`, database credentials, OAuth secrets, Stripe keys, and signing secrets out of Git history.

## Security notes

- Never commit `.env` or expose private keys in frontend `NEXT_PUBLIC_*` variables.
- Never trust a client-provided rental total; calculate prices on the server.
- Never mark a booking paid based only on a browser redirect; require a verified Stripe webhook.
- Do not log authorization headers, cookies, or payment credentials.
- Use Stripe Test mode for development and test cards only.
